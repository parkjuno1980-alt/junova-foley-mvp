# AutoFoley 고객중심 디자인 적용 기록

## 변경 파일

- `index.html`: 기존 헤더, 소개와 시각 자료의 2열 영역, 3개 안내 카드, 좌우 작업 패널을 유지했다. 소개의 시각 자료 자리에 새 영상 등록창을 배치했다. 모바일에서는 기존처럼 1열로 전환한다.
- `docs/DESIGN_REVIEW.md`: 적용 값, 검증 결과, 직접 확인할 내용을 기록했다.

## 스타일

| 변수 | 적용 값 | 역할 |
| --- | --- | --- |
| `--bg` | `#250b24` | 배경 |
| `--ink` | `#bdebd3` | 본문·제목·버튼 글자 |

기본색 3개와 지정된 투명도 파생값만 사용한다. 그라데이션과 그림자는 사용하지 않는다. 타임라인 canvas도 같은 변수를 읽는다. 글꼴은 지정한 Pretendard Variable / Pretendard, 본문 17px·줄 높이 1.7, 제목 30px·데스크톱 44px이다. 본문·배경 대비는 13.88:1, 버튼 글자·강조색 대비는 5.32:1이다. 흰 글자를 추가하지 않았다.

## 흐름과 기존 기능

1. 소개 화면에서 새 영상 파일을 선택하거나 끌어 놓고 ‘등록한 영상으로 계속하기’를 누른다. 영상 선택 전에는 시작 버튼도 파일 선택창을 연다.
2. 기존 작업 패널에서 분석을 시작하고 진행 상태를 확인한다. 기존 브라우저 모드에 필요한 참조 자료와 타임코드는 접은 설정에서 입력한다. 엔진 연결·지난 작업 기능도 접은 설정에 유지한다.
3. 완료 결과에서 AAF를 받고, 이어서 나타나는 파일명·예상 저장 위치와 확인 방법을 읽는다. 다운로드 폴더의 실제 절대 경로나 저장 성공을 웹에서 읽은 것처럼 표시하지 않는다.

기존 합성 출력 체험에는 짧은 대기 단계를 붙였다. 등록한 영상을 분석하지 않는 예시라는 표시를 진행 화면과 결과에 남긴다. 서버 모드도 테스트 엔진인지 구분한다. 실제 분석 엔진이나 Pro Tools 호환성의 새 검증을 의미하지 않는다.

Supabase 신청 처리와 공개 키 설정은 원문 그대로 유지했다. 신청 화면은 주 작업 흐름 뒤의 하단 링크로 이동했다. 화면 점검을 위해 실제 신청을 전송하지 않았다. 엔진 코드와 서버 API는 수정하지 않았다.

## 검증

- 데스크톱 1280×900, 모바일 390×844에서 첫 화면의 등록창과 시작 버튼이 화면 안에 보임을 확인했다.
- 모바일 제목은 의미 단위로 줄바꿈되며, 데스크톱과 모바일 모두 가로 넘침이 없었다. 모바일 기본 버튼은 컨테이너 전체 폭이다.
- 첫 화면 파일 선택 → 작업 화면의 선택 파일명 반영을 확인했다.
- 예시 진행 → 결과 → AAF 포함 ZIP 다운로드 → 저장 위치 안내를 브라우저에서 확인했다.
- 연결 테스트용 엔진에서 영상 등록 → 분석 진행 → 결과 → AAF 다운로드 → 저장 위치 안내를 확인했다.
- 기존 API 테스트 5개 통과, JavaScript 구문과 HTML ID 중복 없음, 신청 처리 코드 동일 확인.
- 최신 main의 지난 작업 다시 열기 기능은 제거하지 않고 유지했다.

## 직접 확인할 항목

- 실제 문구: 스튜디오 소개와 첫 제목이 원하는 말투인지 확인한다. 실제 엔진 연결 전에는 예시 체험 표시를 유지한다.
- 이미지: 새 이미지를 추가하지 않았다. 레퍼런스와 퍼소나 이미지는 서비스 화면에 넣지 않았다. 원본 이미지 파일이 제공되지 않은 상태에서 다른 이미지를 임의로 대체하지 않았다.
- 저장 위치: 브라우저 다운로드 설정과 내려받은 파일명을 확인한다. 같은 이름의 기존 파일이 있으면 브라우저가 파일명에 번호를 붙일 수 있다.
- 실무 결과: 실제 영상의 싱크, 화면 밖 동작과 누락, Pro Tools에서 AAF를 불러온 결과는 별도로 확인한다.

작업 브랜치를 PR로 올리며 main에 직접 push하거나 Vercel CLI로 배포하지 않는다.
