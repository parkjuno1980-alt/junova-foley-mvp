# 웹 ↔ 엔진 연결 인계 (2026-10-23)

## Codex에서 구현한 부분

`server/` 로컬 API, 단일 작업 대기열, 디스크 저장 업로드, 허용 폴더 경로 등록, 진행 상태 조회, 취소, 인물표 확인, 결과 조회와 Range 다운로드를 구현했습니다. 웹 화면은 같은 주소에서 서버를 찾으면 엔진 모드를 추가합니다. 기존 브라우저 분석·합성 출력 데모·Supabase 신청 흐름을 유지합니다.

기본 엔진은 `server.mock_engine`입니다. 화면과 파일 이름에 테스트라고 표시하며 실제 영상 분석을 하지 않습니다. 합성 클릭과 오디오를 포함한 AAF를 만듭니다. 실제 엔진의 분석 정확도나 Pro Tools 가져오기 성공을 의미하지 않습니다.

## Claude가 연결한 실제 엔진 (2026-10-23 밤)

엔진 코드는 이 공개 저장소에 없고, 맥스튜디오 외장 드라이브 `AI 테스트/_분석결과/engine_home/`에 있습니다.

- 실행기: `engine_home/work/junova/run.py` (`python -m junova.run run <job_dir>`, 이 문서의 계약 그대로)
- 서버가 부르는 명령: `JUNOVA_ENGINE_CMD="bash '<engine_home>/mac/junova_engine.sh'"`
  - `mac/env.sh`가 엔진 전용 HOME과 conda 환경 `junova-engine`(저장된 모델과 같은 numpy·scikit-learn 버전)을 준비합니다.
  - 영상 분석(포즈·CLIP·JSync, torch/MPS)은 기존 `foley` 환경으로 돌립니다.
- 서버 시작: `engine_home/mac/start_server.sh` (127.0.0.1:8800, 작업 폴더 `~/JUNOVA_jobs`, 경로 등록 허용 범위 = `AI 테스트`)

   - 분석용 사본 만들기
   - 포즈·흐름·컷
   - 장면·바닥 판단

## 규격 보완

- 다운로드 인증: `POST /api/jobs/{id}/download/{name}`가 5분 동안 해당 파일만 받는 URL을 줍니다. 웹은 이 URL을 브라우저 다운로드로 사용해 GB 단위 Blob을 만들지 않습니다. Bearer 토큰 자체는 URL이나 브라우저 저장소에 넣지 않습니다.
- 엔진 로그 원문에는 비밀 값이나 경로가 섞일 수 있어 API 오류에는 한국어 요약을 반환하고 전체 로그는 로컬 `engine.log`에 보관합니다.
- `GET /api/health`의 `engine.mock`으로 테스트 엔진을 구분합니다. `engine.cmd`는 실제 명령 문자열 대신 `configured` 또는 `mock_engine`입니다.
- 선택 사항인 SSE는 구현하지 않았습니다. 웹은 2초마다 조회합니다. 업로드 이어받기는 지원하지 않으며 큰 로컬 자료는 경로 등록을 권합니다.
- 서버 재시작 시 실행 중이거나 대기하던 작업은 실패로 바뀝니다. 브라우저를 닫아도 서버 작업은 계속되고, 목록 API는 있지만 화면의 작업 복구 목록은 다음 작업입니다.

## 확인 결과

- `python -m pytest server/tests -q`: 5개 통과. 성공, 실패, 대기열, 취소, 인물 확인, 경로·출처·토큰 제한, 다운로드 인증과 Range를 포함합니다.
- 테스트 AAF 재열기: 오디오 트랙 3개, 주 클릭 6개·후보 3개, 오디오 포함, 후보 MonoAudioGain 약 −144 dB.
- 브라우저: 테스트 파일 선택·업로드 → 인물 확인 → 재개 → 결과 표시 → AAF 실제 다운로드와 재열기 확인.
- 로컬 HTTP multipart로 합성 바이트 1,074,790,400바이트 업로드 확인. 해당 실행에서 서버 RSS는 37.7~66.3 MB였으며, 전체 파일 크기만큼 메모리가 증가하지 않았습니다. 업로드 시험 파일은 시험 후 삭제했습니다. 이 수치는 해당 환경의 관측값이며 보장 성능이 아닙니다.
