# JUNOVA 로컬 엔진 연결

웹 화면과 엔진 사이의 API입니다. **기본값은 합성 클릭을 만드는 연결 테스트용 엔진**이며, 영상 분석 모델이 아닙니다. 실제 엔진·모델·녹음 자료는 이 공개 저장소에 넣지 않습니다.

## 로컬 실행 (맥북에서 연결 테스트 / 맥스튜디오에서 엔진 실행)

저장소 루트에서 Python 3.11 이상으로 실행합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r server/requirements.txt
uvicorn server.main:app --host 127.0.0.1 --port 8800 --no-proxy-headers
```

브라우저에서 `http://127.0.0.1:8800`을 열고 ‘폴리 작업실’로 이동하세요. ‘엔진 서버 연결됨 · 연결 테스트용 엔진’을 확인한 뒤 영상 파일 하나로 테스트할 수 있습니다. 테스트 엔진은 영상 내용을 읽지 않습니다. 인물 확인 옵션으로 중간 확인 화면도 시험할 수 있습니다. 기본 출력은 클릭 6개와 후보 클릭 3개, 오디오를 포함한 AAF입니다. 후보 소리는 MonoAudioGain 약 −144 dB로 기록합니다. 실제 Pro Tools 가져오기는 별도 검증이 필요합니다.

기존 브라우저 모드는 ‘엔진 연결 설정 → 작업 방식’에서 선택할 수 있습니다. `python3 -m http.server 8765`나 Vercel에서는 서버 없이 기존 기능을 사용합니다. 신청 폼은 기존 Supabase 연결을 유지합니다.

## 실제 엔진으로 교체 — Claude 쪽에 전달할 계약

`docs/ENGINE_API.md`의 `job.json`, `progress.json`, `result.json`을 따르는 실행기를 준비한 뒤, **서버를 시작하기 전** 환경 변수 `JUNOVA_ENGINE_CMD`에 실행 명령을 설정합니다. 서버는 여기에 `run <job_dir>`를 덧붙여 실행합니다. 셸 문자열을 실행하지 않으며 인수로 파싱하므로 경로에 공백이 있으면 따옴표로 묶어야 합니다. 엔진의 Python 환경이 따로라면 그 Python의 절대 경로를 쓰세요.

실제 래퍼가 지킬 사항:

- 서버가 쓴 입력 경로, fps, 시작 TC, 세션 차이, 생성 옵션을 사용합니다. 타임코드는 임의 고정하지 않습니다.
- 결과 AAF는 오디오를 포함하고 `out/` 안에 저장합니다. `result.json`에는 작업 폴더 기준 상대 경로를 씁니다.
- 상태 JSON은 임시 파일 작성 후 rename으로 교체합니다. 종료 코드 0일 때만 성공으로 처리합니다.
- 인물 확인은 `needs_review`와 `review/people.json`으로 요청합니다. `people_answer.json`을 읽고 진행 상태를 `running`으로 갱신합니다.
- SIGTERM을 받으면 실행 중인 자식 작업도 정리합니다. 서버는 프로세스 그룹을 종료합니다.
- 엔진 전체 로그는 작업 폴더 `engine.log`에만 남깁니다. API 오류에는 로그 원문이나 개인 경로를 노출하지 않습니다.

환경 변수는 `.env.example`에 이름만 제공합니다. 이 서버는 `.env`를 자동으로 읽지 않으므로 실행할 터미널에서 설정하세요. `JUNOVA_DATA_DIR` 기본값은 `~/JUNOVA_jobs`입니다. 실제 작업 폴더는 Git 저장소 밖에 두세요. `JUNOVA_ALLOWED_ROOTS`는 로컬 파일 경로 등록을 허용할 폴더를 쉼표로 나열합니다. 등록 파일을 복사하지 않으므로 엔진 완료까지 외장 드라이브와 원본을 유지해야 합니다.

## 맥북 ↔ 맥스튜디오

이번 구현은 로컬 서버까지입니다. 맥북에서 맥스튜디오로 연결하려면 **맥스튜디오에도 이 브랜치와 실제 엔진 실행기를 설치**해야 합니다. `127.0.0.1`은 각 컴퓨터 자신을 가리키므로 맥북에서 이 주소를 열면 맥스튜디오로 연결되지 않습니다.

초기에는 같은 Wi-Fi와 macOS의 SSH 원격 로그인을 이용해 맥북에서 아래처럼 포트 전달을 구성하고, 맥북의 `http://127.0.0.1:8801`을 열면 화면과 API를 같은 주소로 사용할 수 있습니다. 아래 값은 실제 Mac Studio 사용자와 네트워크 주소로 교체하세요. SSH 계정·키·원격 로그인 설정은 별도이며 자동으로 활성화하지 않습니다.

```sh
ssh -N -L 127.0.0.1:8801:127.0.0.1:8800 MAC_STUDIO_USER@MAC_STUDIO_HOST
```

이 방식이면 맥스튜디오 서버는 127.0.0.1 바인딩을 유지합니다. 공개 Vercel 화면에서 사설 HTTP 서버에 직접 연결하는 구성은 이번 범위가 아닙니다. 외부 인터넷 공개나 터널 서비스는 설정하지 않습니다.

## 인증과 대용량 파일

- 토큰이 없으면 요청의 연결 출발지와 Host가 모두 루프백이어야 합니다. 프록시 헤더를 신뢰하지 않는 위 실행 명령을 사용하세요. 루프백에서는 해당 Mac의 다른 프로세스도 접속할 수 있습니다.
- 토큰을 설정하면 API는 Bearer 인증을 요구합니다. 화면의 ‘엔진 연결 설정’에서 입력하고 연결 확인을 누르세요. 토큰은 탭 메모리에만 두며 브라우저 저장소·URL에 넣지 않습니다. 토큰이 있는 상태에서도 외부 출처는 `JUNOVA_ALLOWED_ORIGINS`에 명시한 주소만 허용합니다.
- 파일 업로드는 `UploadFile`의 디스크 임시 저장과 1 MB 단위 복사를 사용합니다. 전체 파일을 바이트 배열로 읽지 않습니다. 임시 스풀과 작업 디렉터리에 공간이 필요하며, 재개 가능한 업로드는 아직 지원하지 않습니다. GB 단위 자료는 맥스튜디오 경로 등록을 권합니다.
- AAF 다운로드는 HTTP Range를 지원하며 JS Blob으로 전체 파일을 읽지 않습니다. 토큰 인증이 켜져 있으면 `POST /api/jobs/{id}/download/{name}`가 해당 파일만 받을 수 있는 5분짜리 다운로드 URL을 발급합니다. 이 URL도 만료 전에는 공유하지 마세요. 다운로드는 요청 로그에 쿼리가 남을 수 있습니다. 새 이어받기 요청이 만료 후라면 버튼을 다시 눌러 URL을 받습니다.
- GPU 작업은 한 번에 하나입니다. **uvicorn workers는 1개**만 사용하세요. 서버 재시작 때 미완료 작업은 실패로 표시합니다. 브라우저를 닫아도 시작한 서버 작업은 계속됩니다. 최근 작업은 `GET /api/jobs`로 조회할 수 있으며 현재 화면에는 작업 복구 목록이 없습니다.

## 검증

```sh
python -m pytest server/tests -q
```

취소·실패·인물 확인·대기열·경로 탈출·인증·출처 제한·Range·AAF 재열기와 후보 트랙 게인을 검사합니다. 실패 테스트: `MOCK_FAIL_AT=foot`, 인물 확인: `MOCK_REVIEW=1`, 테스트 속도: `MOCK_STAGE_SECONDS`.

구현 참고: [FastAPI UploadFile](https://fastapi.tiangolo.com/tutorial/request-files/), [Starlette FileResponse와 Range](https://www.starlette.dev/responses/).
